# Source style for SM64DS

This is the canonical style guide for reconstructed `src/` and shared `include/`
code. [AGENTS](../AGENTS.md) defines byte/relocation proof; the
[TU conventions](tu-promotion-conventions.md) define production ownership;
[PIPELINE](agents/PIPELINE.md) defines independent review. Compiler experiment
notes are evidence references, not additional style policies. Prefer genuine,
period-appropriate C++ that reproduces retail under `2004/b56`. A passing style
check establishes only its documented checks, not reconstructed semantics.

## Source conventions

| Subject | Default for new or reconstructed code |
|---|---|
| Language | The pinned compiler's C++03-era subset. Use `0` for null pointers; no `nullptr`, lambdas, or modernization for its own sake. Existing genuine C remains C. |
| Pointer tests | `if (ptr)` / `if (!ptr)`. Use explicit comparisons when they explain a scalar condition or preserve measured codegen. |
| Receiver | Omit `this->` unless needed for lookup or clarity. Do not mechanically rewrite proven existing source. |
| Members | Descriptive names following the class's established convention. For newly coined instance members use `mTimer`, `mState`, etc.; retain established names and distinguish inferred names from ROM evidence. |
| Construction | Prefer initializer lists for base/member construction, in declaration order. Assignment in the body is not construction. Preserve measured constructor/destructor order and verify the whole emitted output. |
| Casts | In C++, prefer the appropriate explicit cast (`static_cast`, `reinterpret_cast`, `const_cast`) over a compound C cast. Do not replace a cast without checking its types and generated bytes. C and hardware/ABI boundaries have their own measured requirements. |
| Fields and calls | Use real members, class methods, virtual dispatch, and shared interfaces where established. Offset views, hand-spelled mangled bindings, and manually indexed vtables require an explicit partial-reconstruction disposition. |
| Files and data | Consolidate related methods and owned data into evidenced production TUs. Use `srcpath.py` and the domain/name rules in AGENTS. Define owned data in its TU; use `extern` for actual cross-TU references, not to avoid ownership. Preserve attribution by address. |
| Layout | Four spaces, Allman braces, 100-column target, pointers attached to types. The pinned `.clang-format` is the executable definition. Preserve include and declaration order, pragmas, symbol markers, and evidence comments. |

A short C++ example (names here are illustrative, not ROM claims):

```cpp
//cpp
class Timer
{
public:
    Timer() : mTicks(0) {}
    void Tick();

private:
    int mTicks;
};

void Timer::Tick()
{
    if (mTicks)
    {
        --mTicks;
    }
}
```

Formatting alone does not recover a class. Source review must still examine raw
casts, lifecycle functions, vtables/RTTI, owned globals, and leftover scaffolding.
Keep the first-line `//cpp`: current language-mode tools use it. Removing it needs
a separate tooling migration. Do not copy historical matching experiments that
use raw offsets or compiler tricks as the default source form.

## Local check and formatter

```sh
python -m pip install -r tools/requirements-style.txt
python tools/source_style.py --base origin/main
python -m unittest tools.test_source_style -v
```

The tool pins clang-format **19.1.7**, validates its executable version, and never
rewrites a file. `--clang-format PATH` or `CLANG_FORMAT` selects the executable.
`--base` checks the merge base of that revision and HEAD against the working tree:
committed changes, staged/unstaged edits, and untracked source/header files are
included. A missing base or formatter fails instead of silently skipping.

New files are checked in full; existing files are formatted only at added/changed
lines. Clang-format can expand the requested range to a logical statement; the
checker reports replacements intersecting changed lines. Untouched historical
formatting is not a new error. Explicit `--files path.cpp ...` without `--base`
checks those files in full. Exit 1 means findings; exit 2 means the check could not
run. `--patterns-only` explicitly omits formatting and is not a full style pass.

For a new file, run `clang-format -i path.cpp` and inspect the diff. For an existing
file, use the reported line numbers with `--lines=LINE:LINE` rather than reformatting
its whole TU. The configuration disables include/using sorting and token-changing cleanup
options; evidence comments are not reflowed. Check markers and pragmas afterwards.
Source edits still require the relevant ROM/relocation and consumer gates.

## Pattern regression gate and exceptions

`source_style.py` reports these narrow textual patterns on the mwccarm side of
source, with comments and string/character literals masked:

| Rule | Recognized shape |
|---|---|
| `raw-offset` | `(u32*)(self + 0x74)` and `(char*)self + 0x74`-style object views |
| `manual-vtable` | Member accesses named `vtable`, `vptr`, or `vtbl` indexed as an array |
| `handspelled-member` | `_ZN...` member/namespace bindings in declarations, definitions, or calls |
| `unknown-field` | `unk_` followed by hexadecimal digits |
| `modern-nullptr` | The `nullptr` token |

Existing occurrences are compared per file, rule, normalized matched spelling,
and multiplicity against the base. Whitespace alone does not change that spelling;
a new offset, symbol, or extra occurrence does. Git-detected renames preserve the
old file's debt. A newly copied or added file does not inherit another file's debt.
These rules do not parse C++, prove a shadow layout, detect all indirect dispatch,
or decide whether an encoded name denotes a namespace or member. Other macros are
not preprocessed; only the existing `_MSC_VER` arm helper is applied. The existing
CONVERTED and language-mode ratchets retain their own definitions and checks.

When a newly introduced recognized pattern is required, add a reviewed entry to
`config/source-style-exceptions.json` with exact `path`, `rule`, normalized `match`,
positive total-occurrence cap `count`, `reason`, and `evidence`. Old occurrences
consume that cap even when already banked in the base, so it cannot authorize an
extra occurrence on every PR. No path globs or rule-wide suppression.
Example record shape (not an active exception):

```json
{
  "path": "src/example.cpp",
  "rule": "handspelled-member",
  "match": "_ZN7ExampleD2Ev",
  "count": 1,
  "reason": "Measured ABI bridge retained pending genuine lifecycle reconstruction",
  "evidence": "Link to exact compiler experiment and independent finding"
}
```

This records a review decision; arbitrary prose does not prove a compiler wall.
An exception authorizes only that pattern/count, never byte mismatches or a source
acceptance claim. Remove obsolete entries with their repair. Retained partial
reconstruction must keep a concrete follow-up. Real MMIO with a volatile pointee
and ordinary function-pointer callbacks are legitimate; the fixtures exercise
both. Evidence-based exceptions must pass independent source review.

The `source style` workflow runs the same local tool plus its fixtures. It needs
neither a ROM nor mwccarm. A CI job's presence is not a claim that branch protection
requires it; protection remains a maintainer setting. These diagnostics are a
separate check, leaving the compiler's byte result and source review distinct.

## Clang-tidy compatibility

`.clang-tidy` pins a small advisory allowlist: `bugprone-sizeof-expression` and
`bugprone-suspicious-memset-usage`, with modernization and automatic fixes disabled.
The advisory tool version is **19.1.0** in the requirements file; CI exercises
its configuration on a standalone fixture, not production source. Run against a
specific file with explicit target/language/include arguments, for example:

```sh
clang-tidy tools/style_fixtures/good.cpp -- -x c++ -std=c++03 -target arm-none-eabi -mcpu=arm946e-s
```

A parse error is unsupported coverage, not a clean analysis. Clang's AST is not
mwccarm's code generation; successful parsing is not ROM proof. Evaluation on base `40dfd83ba134be0600730b58f3261f04441632d8` used the command
above, adding `-Iinclude` for production TUs:

| Input | clang-tidy 19.1.0 result |
|---|---|
| `tools/style_fixtures/good.cpp` | Exit 0; no selected diagnostics. |
| `src/GetSoundMode.c` (C99) | Exit 0; no selected diagnostics. |
| `src/game/actors/d_a_yegg.cpp` | Exit 1: `fBase_c.h`'s operator-new parameter type disagrees with Clang's target `size_t`. |
| `src/minigames/d_mg_trmpln2_mario.cpp` | Exit 1: conflicting declarations (`data_ov006_0214059c`, `func_ov006_020e6e3c`, etc.) and an out-of-line member declaration; stopped after 20 errors. |

The two production results are **unsupported coverage**, not passes. Fixing their
contracts is separate matching work, not part of adding style tools. Clang-tidy
therefore stays advisory and is not invoked as a production CI gate. The changed-
code checker does not depend on Clang successfully parsing these legacy TUs.

## Issue #1407 disposition

| Original point | Disposition |
|---|---|
| Function/TU organization and global ownership | Defaults above; production details remain in the TU conventions and AGENTS. |
| Redundant `//cpp` | Retained because tools currently consume it; removal requires a separate language-mode migration. |
| README says C only | Already corrected on main to C and C++. |
| Initialization, pointer tests, receiver, names, casts | Explicit defaults above, with compiler-aware exceptions. |
| Documentation sprawl / poor examples | This is the single style entrypoint linked by CONTRIBUTING; historical measurements remain references. |
| Formatting | Pinned configuration, changed-line local/CI check, and real executable fixtures. |
| Raw offsets / fake vtables / mangled bindings | New-pattern diagnostics with documented limits; existing semantic ratchets and independent review still apply. |
| Build feedback | A nonzero local checker and CI job provide feedback before byte compilation. They do not falsify the compiler result or replace review. |
| clang-tidy | Advisory configuration and measured parsing evaluation; production enforcement depends on supported coverage. |

This is a bounded first implementation of #1407. The issue stays open for any
unsupported production clang-tidy coverage and broader semantic enforcement.
