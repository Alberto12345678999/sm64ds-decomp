Dorifu exposes a production-routing limitation. Five native 24-byte CLPS objects occur at 0x02111b60, 0x02111ba0, 0x02111c40, 0x02111c60, and 0x02111c80 in OV043. Each is followed by eight 0xff bytes whose purpose remains unknown. Repeating `.data` claims for one source makes the pinned DSD reject its configuration with `Section '.data' already exists`. The existing same-name linker selector also cannot distinguish separated contributions. Neither observation establishes a source compiler failure or licenses the intervening bytes as padding.

An initialized section claim can now explicitly route a complete native input section to a unique module section:

```json
{"name": ".data.clps0", "input_section": ".data", "start": "0x02111b60", "end": "0x02111b78"}
```

The module's delinks section and the source's complete range must use that same name. Named routes accept only `.data.<identifier>` or `.rodata.<identifier>` with their matching ordinary `input_section`. Owned object rows stay in the ordinary `data` or `rodata` manifest list. Their complete declared address and size select a unique route; the next symbol is never used to infer object size.

It requires every non-section occupant to be licensed and all input-section bytes to be covered. It then changes section names through the ELF section-name string table. Payloads, symbol records, relocation records, section indices and alignment are unchanged. Source pragmas, fabricated references and padding arrays are unnecessary. Existing ordinary claims retain their behavior.
